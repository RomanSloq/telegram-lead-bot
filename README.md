# Telegram Lead Bot + Mini CRM (P4)

Локальное демо бота для выездных бытовых услуг. Клиент заполняет анкету в личном
чате, подтверждает заявку и получает её ID. Менеджер видит список и карточку
заявок, меняет статус и заметку кнопками. Название демо — **«Выездные услуги ·
демо»**; каталог: сантехника, электрика, сборка мебели, диагностика и мелкий
ремонт.

## Как устроено

- `aiogram` получает Telegram updates обычным long polling, последовательно
  (`handle_as_tasks=False`). Собственного poller и общей дедупликации updates нет.
- `aiosqlite` хранит черновики, заявки и очередь доставок. Подтверждение создаёт
  заявку и задания на сообщения одной транзакцией. Уникальный `source_draft_id`
  возвращает тот же ID при повторном подтверждении.
- Один `DeliveryWorker` отправляет сохранённые сообщения. Handler после commit
  только будит worker. При старте и каждые 30 секунд worker проверяет ожидающие
  доставки. Демо рассчитано на **один запущенный экземпляр** бота.
- Незавершённый ввод заметки менеджера хранится в памяти процесса; сама
  сохранённая заметка, статус, заявки и клиентские черновики хранятся в SQLite.

## Локальный запуск

Нужен Python 3.12+ и Telegram-бот, созданный через BotFather.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
Copy-Item .env.example .env
```

В локальном `.env` укажите:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен демо-бота. Никогда не добавляйте его в Git. |
| `MANAGER_IDS` | Telegram user ID менеджеров через запятую, например `123,456`. Каждый менеджер сначала открывает бота в личном чате и отправляет `/start`. |
| `DATABASE_PATH` | Путь к SQLite; по умолчанию `leadbot.sqlite3` в текущей папке. |

```powershell
.\.venv\Scripts\python.exe -m leadbot.main
```

Демо-сценарий: клиент отправляет `/start`, выбирает услугу, указывает адрес,
желаемое время, имя, телефон и необязательный комментарий. На экране проверки
можно исправить поле или вернуться назад; «Подтвердить» создаёт заявку. Менеджер
открывает `/leads`, затем `/lead <ID>` и пользуется кнопками в карточке.
`/cancel` отменяет текущий клиентский черновик или незавершённый ввод заметки.
Повторный `/start` позволяет продолжить либо заменить активный черновик.

Телефон принимает пробелы, скобки и дефисы; сохраняется с необязательным `+`
и 10–15 цифрами. Каталог, название демо и основные подсказки находятся в `src/leadbot/catalog.py`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp=tmp
.\.venv\Scripts\ruff.exe check .
```

Тесты создают временные SQLite-базы и подменяют Telegram API; ожидания минутных
retry-интервалов нет. Реальные Telegram E2E сценарии требуют локально заданных
`BOT_TOKEN` и `MANAGER_IDS`: клиентская анкета, действия менеджера, восстановление
после рестарта и временный сбой доставки.

## Границы v1

Это воспроизводимое **локальное демо**, без выбранного постоянного хоста и
обещания работы 24/7. Нет web-интерфейса, внешней CRM, LLM, платежей, Redis,
Celery и нескольких экземпляров sender. Успешная отправка Telegram и отметка
`sent` в SQLite не образуют общей транзакции: при аварии между ними уведомление
может повториться; ID заявки делает дубль узнаваемым. Для реального клиента
отдельно нужны размещение, резервное копирование и правила хранения данных.

Операторские действия и резервное копирование описаны в
[`docs/runbook.md`](docs/runbook.md); решения — в
[`docs/decisions.md`](docs/decisions.md).
