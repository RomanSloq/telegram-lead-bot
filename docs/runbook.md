# Операционная памятка для локального демо

## Запуск и рестарт

Заполните локальный `.env` по `README.md`, дайте менеджерским аккаунтам открыть
бота через `/start` в личном чате. Запускайте **один** экземпляр
`.\.venv\Scripts\python.exe -m leadbot.main`. Для штатного рестарта остановите
процесс и запустите снова. Черновики, заявки, статусы, заметки и ожидающие
доставки остаются в SQLite; временный ввод заметки нужно начать заново.

Путь БД задаёт `DATABASE_PATH` (`leadbot.sqlite3` по умолчанию). Файлы `.env`,
`*.sqlite3`, `*.db`, логи и временные файлы игнорируются Git. Не публикуйте
резервные копии БД: в них есть адреса и телефоны.

## Ошибки доставки

`pending` — ещё не отправлялось; `retry` — временный сбой и запланирована
следующая попытка; `sent` — Telegram подтвердил отправку; `failed` — постоянный
сбой либо пять исчерпанных попыток. Worker просыпается при новой заявке и
каждые 30 секунд, а при старте подхватывает due-записи.

Менеджер использует `/delivery_failures`: команда показывает ID доставки,
ID заявки, тип, число попыток и безопасную категорию ошибки без текста заявки.
После устранения причины `/retry_delivery <ID доставки>` возвращает конкретную
`failed`-запись в очередь с новым лимитом попыток. Неполученное уведомление не
удаляет заявку; её можно найти через `/leads` и `/lead <ID>`.

| Категория | Действие |
|---|---|
| `temporary`, `rate_limit`, `unknown` | Worker повторяет автоматически до пяти попыток. Для rate limit учитывает `retry_after`. |
| `recipient_or_request` | Проверьте, что получатель открыл бот и не заблокировал его; проверьте корректность запроса. После исправления повторите вручную. |
| Ошибка авторизации бота в журнале | Исправьте локальный `BOT_TOKEN` и перезапустите бот. Worker не расходует попытки очереди при такой ошибке. |

При аварии после успешного Telegram send, но до записи `sent`, сообщение может
повториться. Сверяйте ID заявки, прежде чем работать с дубликатом.

## Безопасная резервная копия и восстановление

Для работающей SQLite используйте backup API, а не простое копирование
открытого файла. Пример PowerShell из корня проекта (замените пути и храните
копию в защищённом месте):

```powershell
$env:LEADBOT_DB = 'leadbot.sqlite3'
$env:LEADBOT_BACKUP = 'D:\SecureBackups\leadbot-backup.sqlite3'
.\.venv\Scripts\python.exe -c "import os,sqlite3; source=sqlite3.connect(os.environ['LEADBOT_DB']); target=sqlite3.connect(os.environ['LEADBOT_BACKUP']); source.backup(target); target.close(); source.close()"
```

Периодически проверяйте восстановление **на отдельном тестовом пути**. Для
рабочего восстановления остановите бот, сохраните текущую БД отдельно,
скопируйте проверенную резервную копию в путь `DATABASE_PATH` и запустите бот.
Проверьте `/leads` и `/delivery_failures`. Не восстанавливайте старую копию
поверх работающего процесса и не запускайте два worker на одной БД.

## Быстрая диагностика

- Запуск останавливается до polling: проверьте `BOT_TOKEN`, `MANAGER_IDS` и
  доступность пути БД.
- Менеджер не получил сообщение: сначала проверьте `/leads`, затем
  `/delivery_failures` и наличие диалога менеджера с ботом.
- Клиент повторно нажал «Подтвердить»: должен вернуться прежний ID; если
  сообщения дублируются после аварии, сверяйте ID заявки.
- После долгого простоя Telegram может перестать хранить старые входящие
  updates. Локальный demo-процесс не заменяет постоянное размещение.
